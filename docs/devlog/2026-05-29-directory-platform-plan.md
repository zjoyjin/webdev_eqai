# EQAI 目录型测评平台

## 计划目的

- 先把测评目录做成稳定的数据产品。
- 先补基础测试，降低后续改动风险。
- 先同步产品文档，减少“功能到底完成没完成”的误判。
- 把仍未确认的产品问题单独列出，避免提前实现错误方向。

## 测评目录数据服务

当前测评数据一开始更像一整包数据返回，不适合作为长期产品数据服务。页面只需要部分测评信息时，也要读取完整数据，后续做筛选、搜索、排序、上下架和运营维护会比较吃力。

- 当前数据规模包括 20 个测评组和 103 个测评维度。
- 下一步方向是让模块、测评组、测评维度分别读取。
- 保留当前 `/api/assessments` 兼容响应，不做大范围推翻。
- Supabase 初始化 SQL 补充结构化目录表，原有 `assessment_catalog.payload` 继续作为兼容路径保留。

## 测试和文档同步

- 目录 API、页面入口和数据结构变化需要基础测试保护，避免字段缺失和结构变化只能靠人工点页面确认。
- 产品文档需要从历史记录堆叠转成产品和工程共同看的状态图。
- 文档应把当前主线、已确认内容、未确认内容和待后续讨论事项分开写。

## 存疑项

- 联系表单是普通咨询、测评需求收集，还是企业 / 学校 / 家长线索入口仍未确认。
- 表单提交后在哪里查看仍未确认，候选包括 Supabase 后台、WPS 多维表格、邮件通知或后续后台管理页。
- Work、Personal、Kid、Pet 是分类入口、目录筛选页、真实测评入口，还是统一目录页的一部分仍未确认。
- Donate 是否保留、延后或移出当前产品范围仍需确认。
