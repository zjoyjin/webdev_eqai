# EQAI 路线图

## 功能群组与优先级

- 身份、注册与数据保存：匿名试用、自然引导注册、会话保持、聊天和测评结果保存。
- 测评目录与测评体验：正式页面承接结构化目录，明确 Work、Personal、Kid、Pet 四个入口定位。
- AI 体验与长期记忆：AI 基于历史聊天和测评结果继续给建议，并清楚区分建议、依据和不确定性。
- 用户仪表盘：展示最近聊天、最近测评、历史结果和未完成项目，让用户能接续上次中断的位置。
- 设计系统与体验扩展：统一目录页、详情页、结果页、登录注册页和仪表盘体验，保证移动端可用。
- 运营与管理：确认用户数据是否正常保存，让关键错误可见，并逐步建立基础分析和轻量运营能力。
- 增长与留存：邮件、站内提醒、分享摘要、成长卡片和订阅等作为后续 Nice to have。

## 后台实现判断

当前不建议立刻新建独立后台项目。更稳妥的路线是先用 Supabase Dashboard / WPS / SQL，再在现有 Next.js 项目内增加 /admin，后期再考虑外接内部工具或独立 Admin App。

核心原因是后台需求还没有完全确定，过早建设完整后台容易把产品范围做重；中期在现有项目内增加 /admin 成本最低，也最容易复用 Auth、权限、API、UI 和部署。

## 安全边界

- EQAI 保存的聊天、测评结果、用户画像和偏好可能包含心理、教育、家庭、儿童相关信息，应按高敏感用户数据处理。
- secret / service role key 只能在 server side 使用，不能进入浏览器、公开文档、URL 或客户端 bundle。
- 所有暴露 schema 中的用户数据表都必须启用 RLS。
- 普通用户只能访问自己的聊天、测评结果、画像和偏好。
- 管理员权限不能只存在前端，必须服务端校验，并记录后台查看、修改、删除、导出行为。

## 建议阶段

- Phase 1：账号转化与数据持久化。
- Phase 2：正式测评体验与用户仪表盘。
- Phase 3：AI 记忆与个性化推荐。
- Phase 4：设计扩展、运营评估与增长实验。
