# EQAI 产品更新

## 本次完成的三条主线

- 测评目录数据服务：把测评数据从一整包资料拆成模块、测评组、测评维度。
- 基础测试：补齐目录 API 的基础保护，让后续改数据结构不容易误伤页面。
- 产品文档同步：把当前方向和实现状态对齐，减少围绕过期描述反复确认。

## 目录数据变化

之前的数据更像一个大箱子，页面只想展示一个分类，也要先拿到整包数据再翻找。现在的数据可以按产品目录理解：先有大分类，再有测评组，最后是每个测评里的维度说明。

- 测评模块：3 个。
- 测评组：20 个。
- 测评维度：103 个。
- 保留 `/api/assessments` 兼容路径，同时新增模块、测评组、维度三层读取方式。

## 验证结果

- 前端目录测试 4/4 通过。
- 后端 ingestion 测试 17/17 通过。
- Next.js 构建通过。
- 本地 API 读取通过。

## 剩余风险和待确认

- 当前完成的是目录底座，不等于用户已经能在正式页面完成完整的“找测评”路径。
- 旧 payload 兼容路径和新三层目录会短期并存，后续页面应逐步转向新目录读取方式。
- 四个评估页的定位没定前，直接开做页面容易做成“看起来有页面，但不知道用户下一步该做什么”。
- 需要确认正式页面承接方式、上线标准、联系表单用途、表单查看方式、Donate 是否保留，以及评审材料形式。
